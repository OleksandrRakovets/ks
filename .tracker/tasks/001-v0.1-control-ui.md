# T001 - v0.1 control UI

## Status

- [ ] Planned

## Why

The first usable release must feel good while a live match is actually being played. Right now the codebase has the engine and sync path, but not the app-level control surface needed for Strila and polished Pyramid play.

## Outcome

An operator can create and run a sparring match for Strila or any supported Pyramid game from phone or laptop without touching raw event JSON or debug screens.

## Scope

- restore or replace the disabled create-match flow with a minimal setup screen,
- keep low-level reusable UI in `packages/ui`,
- build app-level game control molecules selected from gameplay projections,
- support Pyramid control interactions cleanly on small screens,
- support Strila through app molecules driven by `availableCommands`,
- keep the current live sync path working across multiple open devices.

## Proposed Slice Order

1. Re-enable minimal match setup.
2. Define the app-facing control projection contract the route consumes.
3. Replace the current Pyramid-only control route with per-game control selection.
4. Ship Pyramid control molecules.
5. Ship Strila control molecules.
6. Tighten responsive layout and multi-device behavior.

## Acceptance

- create a match from the app UI,
- play a full Pyramid match from phone or laptop,
- play a full Strila match from phone or laptop,
- second device reflects score/state updates quickly enough for live use,
- no route depends on hand-crafted raw event payload editing.

## Explicitly Deferred

- player lookup and dedup,
- guest invite/access model redesign,
- public scoreboard route restore or redesign,
- Strila public scoreboard rendering,
- manager auth,
- managed persistent scoreboards,
- tournament administration.

# T003 - v0.3 managed scoreboards

## Status

- [ ] Planned
- [ ] Blocked on `T002A - v0.25 Better Auth and manager/player foundations`.

## Why

Broadcast use should not depend on exposing a one-off scoreboard URL per match forever. Operators need a small set of persistent scoreboard surfaces that can be attached to whatever live match they are currently streaming.

## Outcome

KS supports persistent read-only scoreboard URLs that an authorized operator can reuse across streams by attaching them to active matches.

## Dependency

- This task builds on the signed-in manager auth and ownership model introduced in `T002A`.
- Reuse the guest-sharing model from `T002` where device-level collaboration still matters, but do not use it as the long-term owner model for persistent scoreboards.
- Reuse the `T002A` ownership model for scoreboard ownership and attach/detach authorization instead of introducing a separate scoreboard-only auth scheme.
- Do not add a new broad secret path just to manage persistent scoreboards.

## Scope

- persistent scoreboard records and stable URLs,
- operator-facing attach/detach flow authorized through the `T002A` ownership model,
- scoreboard-to-match mapping stored in DB,
- SSE-backed live updates from the current match,
- keep scoreboard surfaces read-only.

## Proposed Slice Order

1. Confirm `T002A` ownership rules are in place and can authorize scoreboard ownership/management.
2. Add scoreboard entity and URL model.
3. Add attach/detach storage and service layer.
4. Add operator UI to choose a live match for a scoreboard.
5. Point public scoreboard route at scoreboard ownership/attachment rather than raw match URL usage.
6. Verify update behavior during active match switching.

## Acceptance

- an authorized operator can keep a persistent scoreboard URL,
- that scoreboard can be attached to a live match,
- switching the attached match updates the displayed live data correctly,
- viewers cannot edit anything from the scoreboard surface.

## Explicitly Deferred

- tournament brackets,
- advanced broadcast overlays,
- non-SSE transport experiments unless SSE proves insufficient.
